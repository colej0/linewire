Alea is Linewire’s self-learning AI research project. It is not a rules engine. The work is deep reinforcement learning on historical and simulated data. Research comes first.

The question

Most “algo” systems are still rule books.

If this indicator crosses that line, buy. If it crosses back, sell. Those systems only do what a person already encoded. When the data changes, the rules go stale, and someone has to rewrite them.

Alea is a research effort to do something different: train an agent that improves its own policy from experience, using deep reinforcement learning, rather than executing a fixed script.

How it learns

A policy, not a script.

  1. Experience, then update. The agent interacts with historical data and, in training, a simulated environment. It updates a policy so that actions improve a training objective over time, instead of executing fixed if-then rules.
  2. Evaluate offline first. A policy is tested offline before it would ever be allowed to run with any capital. Training and evaluation are kept separate.
  3. Limits the agent cannot ignore. Any later autonomous run would stay inside operator-set constraints: position limits, loss limits, permitted instruments, and a kill switch.
  4. Research first. The current job is to train and understand the learned policy. This site does not publish performance figures.

Compute

Why this needs GPU time

Deep reinforcement learning on historical and simulated data is compute-heavy. The bottleneck is GPU time, not a spreadsheet of rules.

Cloud credits, if awarded, would be used to train and evaluate research policies: GPU instances or managed training jobs, data storage, experiment tracking, and offline inference tests.

Credits offset cloud usage. They are not cash and they cannot buy a physical computer. No trading performance is implied by this research work.
